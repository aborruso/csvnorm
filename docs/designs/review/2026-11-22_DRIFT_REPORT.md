### Document contradicts its own "Esito dell'implementazione"

These sections were not updated after the implementation deviations were agreed. The code follows the Esito section, so the document is the side that is wrong.

- **Hybrid detection by size missing from the rest of the doc.** Esito: "fino a 50 MiB (`FULL_DETECTION_MAX_BYTES`) resta il rilevamento sull'intero file". Code: `src/csvnorm/encoding.py:34` and `:304-306`. Still describing sampling for every file: Overview (line 32, "rilevamento dell'encoding con una decodifica UTF-8 stretta; se fallisce, `charset_normalizer` su un campione"); Piano tecnico > Rilevamento (lines 211-215, the three-step strategy with no size threshold); detailed plan phase four, `detect_encoding` (line 614-616, "Chiama `_scan`..."), where the constant `FULL_DETECTION_MAX_BYTES` is not listed among the module constants (lines 572-577).
- **Memory goal exceptions do not list the files up to 50 MiB.** Obiettivi > Memoria (line 91): "la memoria dei passaggi Python ... resta sotto i 24 MiB qualunque sia la dimensione del file ... Fanno eccezione ... BOM UTF-16 o UTF-32, BOM UTF-8 seguito da UTF-8 non valido, byte NUL, conversione fallita". Code: every file up to 50 MiB goes through `from_path` on the whole file (`encoding.py:304-306`), and ASCII files with ISO-2022/HZ escapes go there too (`encoding.py:206-207`). The goal as written is not what the code delivers; `PRD.md:55` already lists the 50 MiB case.
- **Windows "in sospeso" between chunks.** Plan phase four (line 606): "Le finestre che non si possono completare perché toccano la fine del blocco restano in sospeso fino al blocco successivo. Si tiene una coda di `WINDOW_HALF + MAX_CUT_SEARCH` byte". Esito says each window is read with a `seek`; code does that (`encoding.py:109-120`, `_window`). Line 606 is obsolete.
- **Inward shrinking of a window.** Plan (line 604): "verso l'esterno, per al massimo `MAX_CUT_SEARCH` byte ... si cerca un byte di `CUT_BYTES`". Code also searches inward toward the target byte when the outer band has no cut byte (`encoding.py:131`, `:145`). Covered by Esito ("la finestra si stringe verso il byte"), not by the plan.
- **Sample with no candidates.** Cosa non cambia (line 269): "Se il campione non dà candidati, `ValueError` come oggi (`encoding.py:63-65`)", and plan line 611 (`_pick_encoding` "Solleva `ValueError`"). Code routes to full detection instead (`encoding.py:320-323`), as Esito says ("Campione senza candidati ... rilevamento completo").
- **ISO-2022/HZ route and its reason are missing from the plan.** Plan line 587 lists the `reason` values for `route="full"`: `"utf-16/32 bom"`, `"nul byte"`, `"utf-8 bom with invalid utf-8"`, `"no cut point for byte 0xXX"`. Code adds `"7-bit escape sequences"` (`encoding.py:206-207`, helper `_has_7bit_escapes` at `:159-168`), and line 595 ("Se tutti i blocchi sono `isascii()`: `ascii`") no longer holds for ASCII files containing `ESC` or `~{`.
- **Western preference on the sample.** Plan line 616: with `sample`, "chiama `from_bytes(...)`, poi `_pick_encoding` e `normalize_encoding_name`". Code first returns a Western codec if one is among the least chaotic candidates (`encoding.py:327-331`), otherwise `_pick_encoding` followed by `_prefer_western_if_same_text` (`encoding.py:261-280`, `:332-334`). Matches Esito, not the plan.
- **Fallback when full detection returns the same codec.** Plan line 621-622 ("chiama `_detect_encoding_full`, richiama `on_detected` e riconverte una sola volta"). Code raises the first error without converting again when the codec is unchanged (`encoding.py:377-379`). Matches Esito ("Ricaduta"), not the plan.

### Names, constants, signatures and messages

- **`MAX_WINDOWS` does not exist; `MAX_ATTEMPTS` is not in the plan.** Plan line 574: "`MAX_WINDOWS = 129`". No such constant in `src/csvnorm/encoding.py`; instead `MAX_ATTEMPTS = 8` (`encoding.py:41`), mentioned only as a number in Esito. Doc side is stale.
- **`MAX_ATTEMPTS` is a per-chunk cap, not a per-value cap.** Esito: "Al massimo 8 occorrenze tentate per valore ... poi rilevamento completo". Code resets `attempts = 0` for every `SCAN_CHUNK` (`encoding.py:229`) and returns `full` only when 8 attempts fail inside one chunk (`encoding.py:240-241`); a value that fails fewer than 8 times in each of several chunks is retried in every chunk, so the total can exceed 8. The end-of-file check (`encoding.py:244-246`) still catches values never covered, so the result is correct, but the documented bound does not hold. Either the code should keep the counter across chunks or the doc should say "per blocco".
- **`_pick_encoding` signature.** Plan line 611: `_pick_encoding(result: CharsetMatches) -> str`. Code: `_pick_encoding(result: CharsetMatches, file_path: Path) -> str` (`encoding.py:75`), the path is used in the `ValueError` message. Doc side stale.
- **Route log messages.** Plan line 614: "`Encoding route: sample (N windows, M byte values)`". Code: `Encoding route: sample ({windows} windows, {high_values} byte values, {len} bytes)` (`encoding.py:310-313`), plus two messages not in the doc: `Encoding route: full (file below the sampling threshold)` (`encoding.py:305`) and `Encoding route: full (no candidate for the sample)` (`encoding.py:322`). Doc side stale.
- **First-error window can be dropped silently.** Plan line 602 and Piano tecnico line 215: the sample has "una finestra attorno al punto del primo errore UTF-8". Code adds it only if `_window` finds cut points (`encoding.py:214-216`) and otherwise goes on without it and without routing to `full`. The byte at the error position is still covered through its own value window, so the invariant "every high byte value is in the sample" holds; the behaviour is just not described.
- **Disk-full panel text.** Plan line 522: `show_error_panel("No space left on device\n\nFree some space or set TMPDIR to another disk, then retry.")`. Code: `"No space left on device\n\nFree some space on the output disk or on the temp disk (or set TMPDIR to another disk), then retry."` (`src/csvnorm/core.py:46-50`). Code text is more precise; doc side stale.
- **Non-ENOSPC `OSError` during conversion.** Plan line 525 ("altrimenti «Cannot write temporary file\n{e}»") and test plan line 552 ("dà «Cannot write temporary file»"). Code: `"File error during encoding conversion\n{e}"` (`core.py:564`), and the test asserts the code text (`tests/test_integration.py:538`). Changed in commit `b431d77` ("clearer conversion errors") without a note in the doc. Doc side stale.
- **`_warn_if_low_disk_space` arguments in stdout and `--check` mode.** Plan line 517: "in modalità stdout `output_dir` è `None` e l'output provvisorio sta nella directory temporanea, quindi si somma lì". Code passes `temp_dir` as `output_dir` in stdout mode and `None` only with `--check`, where no output is written (`core.py:829-838`). The stdout estimate is the same; the `--check` case (no output need) and the fact that any `OSError` during the check is swallowed (`core.py:75-78`, commit `b431d77`) are not in the doc.
- **`_normalize_and_refresh_errors` default.** Plan line 476: "riceve un nuovo parametro `crlf: bool`, solo per nome". Code: `*, crlf: bool = False` (`core.py:406-407`). Harmless; the doc omits the default.
- **Comment at `validation.py:34`.** Plan line 470: the comment "diventa «DuckDB keywords whose `_` prefix is removed in the COPY select list»". Code keeps the old first line ("SQL keywords that DuckDB prefixes with underscore when using normalize_names=true.") and adds the new text below it (`src/csvnorm/validation.py:33-35`). Cosmetic.

### Tests and fixtures

- **`empty_file` golden case.** Plan line 404: "`empty_file` (nessun output; exit code e messaggio come registrati con la 1.3.0)". Manifest: `output = true` (`tests/fixtures/golden/cases.toml`, case `empty_file`), expected file `tests/fixtures/golden/expected/empty_file.csv` contains `column0\n`. The 1.3.0 behaviour (exit 0 and a `column0` output) was recorded correctly, as noted in `tasks/todo.md` 1.2; the doc's "nessun output" is wrong.
- **Equivalence test departs from the plan for `windows1252_quotes.csv`.** Plan line 435: "Il valore iniziale è quello che `detect_encoding` dà oggi ... Per ogni voce il test controlla che `detect_encoding` restituisca il valore atteso". Code: `EXPECTED` holds `cp1252` for that file (`tests/test_encoding_equivalence.py:30`) while detection returns `cp437`, and the case is marked `xfail(strict=False)` through `KNOWN_WRONG` (`tests/test_encoding_equivalence.py:43-49`). With `strict=False` a future change in that result passes unnoticed. The golden case for the same file fixes the cp437 output (`ôLibroö`, `10Ç`) as the contract (`tests/fixtures/golden/expected/windows1252_quotes.csv`). The doc does not describe the `KNOWN_WRONG` mechanism; one of the two sides should be aligned.
- **Stale header comment in the manifest.** `tests/fixtures/golden/cases.toml:1-4`: "Expected files ... were generated with csvnorm 1.3.0 ..., except cases with xfail_until, written by hand". No case has `xfail_until` any more, so the comment no longer says which expected files (`keywords_semicolon`, `cp1252_cr_in_cell`, `latin1_crlf_in_cell`) were written by hand.
- **Disk-full test during conversion mocks a different function.** Plan line 551: "con `convert_to_utf8` che solleva `OSError(errno.ENOSPC, ...)`". Test patches `_handle_local_encoding` (`tests/test_integration.py:495-498`, also `:529` for the non-ENOSPC case and the decode-error test), so `detect_and_convert` and `convert_to_utf8` are not exercised on that path. Coverage gap on the test side.
- **Fallback test is weaker than planned.** Plan line 649: "la codifica restituita è uno fra `cp1252`, `latin-1` e `iso8859-15`". Test asserts only `used != "shift-jis"` and that `café` is in the output (`tests/test_encoding.py:349-352`).

### Benchmark script

- **Peak RSS.** Plan line 453: "riporta il picco di RSS con `/usr/bin/time -v` se c'è". Code uses `resource.getrusage(RUSAGE_CHILDREN)` (`scripts/bench_large.py:76-85`), because `/usr/bin/time` was missing (commit `9343f4b`, `tasks/todo.md` 1.7). Doc side stale.
- **Stage list after phase four.** Plan line 634: "`detect_and_convert` sostituisce `detect_encoding` più `convert_to_utf8`".
